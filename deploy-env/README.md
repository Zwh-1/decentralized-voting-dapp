# 部署交接材料。

这里放**移交部署时需要的输入**，与项目代码分开，因为它们不是应用的一部分：
一个是服务器上要填的 `.env` 模板，一个是 GitHub 网页上要填的清单位置。

| 文件                 | 给谁看                             | 上传到服务器吗 |
| -------------------- | ---------------------------------- | -------------- |
| `server.env`         | 服务器上的 `/srv/voting/.env` 模板 | **是**，见下   |
| `github-actions.txt` | 在 GitHub 网页上填变量与密钥时对照 | 否             |

## server.env 不是可直接使用的配置文件

它里面是**中文注释 + 占位符**（形如 `【你定：…】`），没有真实值。
真实口令必须由你在服务器上就地创建，不经过聊天记录、不经过 scp。
原因见 `ops/handoff/upload-to-server.sh` 里那段凭据检查的注释。

字段名以 `docker-compose.yml` 实际读取的为准，21 个字段全部验证过：
把占位符换成真值后跑 `docker compose config`，渲染结果里**没有一个字段落空**，
而且故意去掉 `WEB_IMAGE` 会让它报错——证明检查不是空转。

## 为什么单独放一个目录

原始需求是"给我一个能上传的东西"。把这个目录与 `ops/` 分开，是为了让
"哪些文件要传、哪些只是给人看的"在目录层面就可见，而不是藏在一个文件清单里。
