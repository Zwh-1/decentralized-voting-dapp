# ADR-0023 - 一人一票的约束必须留在链上：采用工厂 + 每投票一份合约，而不是一张合约内用 `pollId` 分表

- 状态：已接受
- 日期：2026-09-21
- 取代：规格 §11 非目标 3「不做多轮次选举、提案制、委托投票」中的「不做多轮次选举」部分（见下文「对既有非目标的取代」）
- 相关：ADR-0001、ADR-0005、ADR-0009、ADR-0017

## 背景

原先项目只有一份 `Voting.sol`，选举是固定的：三个候选人写死在部署期，一个地址只能投一次（`mapping(address => bool) hasVoted`），投出后不可更改。用户要求项目具备实际作用：**任何人都能创建自己的投票，并修改、删除自己的投票**。

这带来一个必须当场决定、且事后极难更改的问题：多个投票在链上如何共存？

有两种做法：

1. **一张合约内分表**：`mapping(uint256 pollId => mapping(address => uint256)) votedFor`，一份合约承载所有投票。
2. **工厂 + 每投票一份合约**：`VotingFactory.createPoll(...)` 用 EIP-1167 最小代理克隆出一份 `Poll` 合约，每份合约自己持有选项、白名单、票数与押金。

## 决策

采用**工厂 + 每投票一份合约**（方案 2）。

`VotingFactory` 保存一份实现合约地址，`createPoll` 克隆它并调用 `initialize` 完成初始化。工厂自身**不持有任何票数，也不持有任何以太**：它只是一份地址登记簿。所有计票、押金与状态都留在各自的 `Poll` 合约里。

同时规定：`Poll` 的 `changeVote` 与 `withdrawVote` 只能改写**同一个** `mapping(address => uint256) votedFor` 槽位，不得引入第二份计数。

## 理由

**方案 1 会把「一人一票」从链上事实降级为链下推断**，这是本决策唯一但决定性的理由。

在方案 2 下，「这个地址在这个投票里投给了谁」的答案由 `Poll.votedFor[address]` 这个链上 mapping 直接给出。它是 EVM 状态的一部分，任何人都能在 Etherscan 上读到，任何索引器都能独立重算，前端不需要相信后端。

在方案 1 下，合约只能维护 `votedFor[pollId][address]`，这本身仍然在链上——但一旦要回答「这个投票现在有几个票」，就必须遍历地址，链上无法做到。于是链上只能存一个**增量计数器** `voteCount[pollId][optionId]`，而这个计数器与 `votedFor` 是两份可以互相矛盾的数据。合约必须自己保证两者同步，任何一处遗漏都会造成「计数与投票人不一致」，并且**链上没有任何办法发现这种不一致**——因为链上已经不存在「独立重算」的能力了。

换句话说：方案 1 并没有让一人一票离开链，而是让**「票数等于投票人数」这个恒等式离开链**。而这恰恰是本项目调用链的全部意义所在（ADR-0001：链上是唯一事实源，链下只做只读投影）。ADR-0017 要求一致性检查比较「同一个瞬间的两份描述」，这个检查只有在链上那份描述可以独立重算时才成立。

方案 2 让每份 `Poll` 的 `results()` 成为该投票票数的权威答案，索引器只是它的投影。一致性检查因此仍然有意义：两边算的是同一件事，分歧就是真故障，而不是两种口径。

次要理由：

- **隔离**：一份 `Poll` 的 bug 或重入只影响该投票（ADR-0005 明确把质押当作真实重入面来构造）。方案 1 分摊状态，一次越权写入可能污染所有投票。
- **权限自然分级**：`Poll` 的 `Ownable` 就是创建者，选项增删改只允许创建者在 `Setup` 阶段做（`onlyOwner` + `InvalidPhase` 双重约束）。方案 1 需要在每个写函数里手工校验 `pollId` 的创建者，是更容易写错的一类检查。
- **克隆而非重新部署**：EIP-1167 代理让创建一笔投票的 gas 从「重新部署整份合约」降到约 4 万 gas，创建投票因此对普通用户可行。这也是本方案在成本上不输给方案 1 的原因。

## 代价与已知边界

- **克隆合约在区块浏览器上显示为代理**，源码需读实现合约地址。已通过 `verify:sepolia` 验证实现合约源码，并在脚本输出中明确说明这一点。
- **`initialize` 可以被直接调用一次**：直接对裸实现合约地址调用 `initialize` 会成功，因为实现合约自己没有「已被克隆」的概念。`Poll` 用 `bool private _initialized` 挡住重复初始化（防克隆劫持），但首次直接初始化在技术上无法阻止。工厂**从不登记也不列出**该地址，索引器只跟随 `PollCreated` 事件，因此这个事实在系统内不可达；测试 `test_Implementation_CannotBeInitialized` 断言并记录了这一点，而不是假装它不存在。
- **`removeOption` 会重排选项 id**：`Poll` 只允许在 `Setup` 阶段、且该选项没有票时删除，删除后压缩数组、后续 id 前移。索引侧因此**不尝试重放重排**，只记录事件；一致性检查比较的是「当前链上 `results()`」与「索引票数」，只要没有在 Setup 之后删选项（合约禁止），两者就不会因重排而分歧。这一点已在索引器代码注释与测试中写明。
- **迁移成本**：旧合约 `0x564a8c64…` 的选票数据在新前端中不可读。旧合约是单人租户且没有外部消费者，因此不提供兼容层——兼容层会让 `decode.ts`、`data.ts`、`ui:drill` 长期分叉。这是被明确接受的一次性代价，已向用户披露。

## 对既有非目标的取代

规格 §11 非目标 3 写着「不做多轮次选举、提案制、委托投票」。本决策**明确取代其中「不做多轮次选举」一句**，因为用户已直接要求多投票能力。

**未被取代的部分**：「提案制」（治理流程）与「委托投票」仍然是非目标。特别是委托投票——它会直接破坏一人一票，而一人一票是本决策全力保全的东西，因此二者不可同时成立。

依据 Aegis 约定，非目标不得被静默违反；规格 §14 已记录这次校正，本 ADR 是它的决策依据。

## 验证

- `contracts/contracts/VotingFactory.t.sol`：12 条测试，覆盖创建、事件、任何人都可创建、**两个投票不共享票数与押金**、**每个投票有各自的 admin**、克隆二次初始化被拒、实现合约不被工厂登记、`allPolls` 按创建顺序、克隆全生命周期。
- `contracts/contracts/PollProperties.t.sol`：40 投票人 × 3 选项 × 1000 轮，每轮重查 4 条不变式；对 vote/changeVote/withdrawVote 交错执行，并断言四类结果各自都真实发生过（`accepted`、`changed`、`withdrawn`、`refused` 均 `> 0`）。
- 负向对照（变异测试）：注释掉 `changeVote` 中的 `--_options[previous].voteCount;` 后，不变式测试如期失败，报出 `the tally must equal the number of current voters: 9 != 8` 等四类错误。这证明上述不变式具备失败能力，而不是恒真断言。
