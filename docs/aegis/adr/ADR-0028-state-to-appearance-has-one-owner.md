# ADR-0028 — 状态到观感的映射只有一个所有者

日期：`2026-09-21`
状态：`已接受`
范围：`web`

## 背景

改造前，每个组件各自决定「一个投票现在是什么状态、应该长什么样」：

| 组件                   | 它自己的判断                                                              |
| ---------------------- | ------------------------------------------------------------------------- |
| `PollCard.tsx`         | `open ? "bg-emerald-50 text-emerald-700" : "bg-slate-100 text-slate-600"` |
| `PollBallot.tsx`       | 阶段文字来自 `phaseText()`，但没有任何颜色                                |
| `ConsistencyBadge.tsx` | 又一套 `ok/warn/bad/neutral` 色板                                         |
| `OptionRow.tsx`        | `bg-slate-900` 进度条                                                     |

四处独立意见，且**互相可以不一致**。这是界面「看起来随意」的机制性原因，不是审美问题：一个读者无法学会「绿色＝可以投票」，因为绿色在不同卡片上意味着不同的事。

更要紧的一点与观感无关：**「投票已过截止但尚未关闭」这个状态，界面把它显示成了「已结束」**。二者的区别是实质性的——合约在 `endsAt` 之后拒绝 `vote`，但阶段**仍是** `Voting`，因此 `refund()` 也会拒绝；读者若被告知「已结束」，就会去找一个必然失败的退款按钮，而真正的补救（任何人都可调用 `closeAfterDeadline()`）反而看不见。

## 决定

新增 `web/src/lib/presentation.ts`，由它**独占**「链上状态 → 呈现在读者眼前的东西」这一映射：

- `phaseTone(phase, deadlinePassed)` 返回 `{ label, tone, votable }`。四个状态互相区分：未开始 / 投票中 / **已过截止（但仍未关闭）** / 已结束。
- `badgeClass(tone)` 与 `accentClass(tone)` 是**唯一**产出这些类名的地方。
- `sharePercent(count, total)` 负责占比计算。

`tone` 以**含义**命名（`live` / `waiting` / `closed` / `danger` / `info` / `neutral`），不是以颜色命名。调用方不需要判断「未开始算 warning 还是 neutral」——那个判断本身就是这个模块的全部内容。

## 理由

### 为什么是纯函数模块，而不是组件或 hook

`web/test/**` 跑在 `node --test --import tsx` 上，无法 import 任何牵扯 React 或 wagmi 的东西（`ERR_MODULE_NOT_FOUND`）。写在组件里的主题是不可测的。而这里真正值得测的失败**不是视觉的**：是某个状态被映到了错误的 tone，于是已关闭的投票渲染成与进行中相同的绿色，读者以为自己还能投票。**这是一个穿着颜色外衣的正确性缺陷**，而它可以在这里被测到。

`deadlinePassed` 由调用方传入而非在函数内读时钟，因此结果是参数的函数，测试可以钉住边界两侧而不必 mock 时间。

### 为什么返回完整字面量而不是拼接

`badgeClass` 返回 `"bg-emerald-50 text-emerald-700 ring-1 ring-emerald-200"` 这样的完整字符串，而不是用 `"bg-" + tone + "-50"` 拼。Tailwind 靠扫描源码文本发现类名，**它看不见的类名就不会被生成**——拼接出来的类在开发时看着正常，生产构建里元素完全没样式。

### 为什么 `votable` 与 `tone` 是两个字段

「这个投票现在是不是投票中」与「我这个地址现在能不能投票」是不同的问题。前者是全局事实，后者取决于读者是谁（是否在白名单、是否已投）。把二者合并会让徽章宣称一个合约并未进入的阶段。`votable` 是前者，供卡片选择按钮措辞；后者由 `ballot-reasons.ts` 负责（见 ADR-0027）。

## 后果

### 正面

- 列表卡片与详情页**不可能**对同一个链上状态给出不同说法：两处都调用 `phaseTone`。
- 「已过截止但未关闭」这一状态第一次在界面上可见，且与「已结束」明确区分。
- 4 个组件里散落的颜色字面量收拢成一处，`presentation.test.ts` 的 14 条用例钉住了它，其中包括「每个 tone 都必须映射到真实类名」与「live 与 closed 必须不同色」。

### 负面

- 多了一层间接。改一个徽章的颜色要改 `presentation.ts` 而不是就地改组件——这是**有意的代价**：就地改正是此前四处意见不一致的成因。
- `ConsistencyBadge.tsx` **保留**了自己的 `ok/warn/bad/neutral` 色板，未并入 `tone`。这不是遗漏：它描述的是「索引与链是否一致」，与投票阶段是正交的维度，强行共用会让一个维度新增取值时另一个维度被迫给出无意义的映射。它改用 ring 而非 border 并与 `Badge` 的形状对齐，但色板独立。

## 相关

- ADR-0017（比较的是同一个瞬间）—— `phaseTone` 接收 `deadlinePassed` 而非自己读时钟，是同一原则在展示层的应用。
- ADR-0027（准入规则住在纯函数里）—— 同一约束（`web/test/**` 不能 import React）导致的同类决定。
- ADR-0009（按钮可用性读自链上）—— `votable` 只反映链上阶段，不猜测。
